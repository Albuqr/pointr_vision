# Calibration review fixes (2026-10-13)
Source: three independent reviews (contract-guardian, reliability-reviewer, code-reviewer) of v0-calibration vs main. Verdict: CHANGES REQUIRED, no BLOCKER, several MAJOR. Found by 2+ reviewers: (a) projection guard never fires, so points on or past the image horizon get (0,0) with in_court=true (cv2.perspectiveTransform returns 0 near w=0 under OpenCV 5.0.0); (b) a projection ValueError in the writer thread kills the writer and loses the rest of the session; (c) idle webcam calibration frame is captured at the default resolution (often 640x480) but recording requests 1280x720, so main.py refuses to record; (d) validator is looser than calibration.schema.json; (e) DATA_CONTRACTS section 8 says the check error is beside each distance and speed, but the code prints it once in the header. Single-reviewer findings: check points can duplicate or alias fit points (hold-out leakage); a corrupt active.json for one camera blocks every camera and wipes the previous group's summaries; commit order broke CLAUDE.md rule 2; calibration_fit saves extra point keys; custom courts scale fixed-length FIBA features; the court diagram draws the key in the wrong place; collinear points give HTTP 500; no upper bound on max_check_error_m.

## Group A: data integrity (all required)
1. Projection guard: explicit homogeneous divide; if |w| < eps, w <= 0, or the result is non-finite, return invalid. Invalid rows get empty x_m, y_m, in_court (never 0, never true) and are counted. Reject at validate/save any homography that is non-finite, singular or has a condition number above a stated limit; save_anyway must not bypass this.
2. Writer survival: a projection or row error never stops the writer thread. Catch per row, write empty position fields, count it, one rate-limited event. Test with a NaN box, a 1e308 homography and a singular matrix: session finishes with status finished and every frame row present. Inject the projector (PositionMap) into SessionWriter; the writer must not import and rebuild CalibrationPositions per item.
3. Report: exclude invalid positions from path length and max speed and say how many; stop calling projection failures "malformed CSV rows"; add calibration id and mean check error to the calibrated caveats.
4. Idle webcam resolution: open the calibration frame with exactly the capture settings the recorder uses and store the real image_size. At record time compare the first frame size; on mismatch that camera fails loudly in the UI with both sizes, other cameras keep recording. If the frame size changes mid-session, stop applying the homography (empty positions plus an event). Fix any UI text that overclaims resolution.
5. One bad calibration must not block all cameras: load every camera's calibration BEFORE changing group_id or clearing summaries; a camera whose calibration is missing, corrupt or invalid starts uncalibrated with an event and a visible UI warning; never return 422 for the whole group.
6. Hold-out integrity: reject a check point coinciding with a fit point (1e-6 m or 1 px); remove alias landmark names; require non-collinear, well-spread fit points with a clean 422 (never a 500); recompute check_mean_m and forced from per-point residuals in the validator; cap max_check_error_m at 2.0 m.
7. Validator = schema: validate_calibration enforces calibration.schema.json (jsonschema), requires court.landmarks, enforces fiba_full 28x15; calibration_fit whitelists point keys. A saved file always passes the schema; a bad file fails validation and never raises inside HttpPreview.

## Group B: needed for the tape test and non-FIBA courts
8. Generate the court diagram from the same landmark constants the fit uses (key at 5.05 to 9.95 m, free-throw line 5.8 m; remove the stray M1 75H279 line). Test the drawn geometry against the landmark table.
9. Custom courts: fixed-length features (key width, key depth, basket offset) stay fixed, or reject custom dimensions until correct. Also support a "custom point" role where the user types measured x,y metres for an arbitrary floor mark, with the same hold-out rules (this is the tape-measure test).
